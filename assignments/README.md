# 作业（TASK1—TASK4 大作业 + 逐讲作业 HW）

总评中的作业部分由两块组成：**四项大作业 TASK1—TASK4 占 30%**（各 100 分、各占总评 7.5%），
**逐讲课后作业 HW 占 10%**（总评 10 分起计，只记及时有效提交）。任务范围、分值与截止以本目录和各讲说明为准，
**优先于历史讲义中的旧作业描述**。

> **当前状态（2026-11-19）**：本课程目前**只布置逐讲课后作业 HW**，按讲次随课件公布、课后提交；
> **TASK1—TASK4 四项大作业尚未布置**——下表列出的发布/截止讲次是 V5 教学大纲中的计划位置，不是已生效的日期，
> 实际以教师课上公布为准。学生现在只需要关注各讲 README 与钉钉群里的 HW 通知。

> **命名变更（2026-11-18）**：原「HW1—HW4」四项大作业更名为 **TASK1—TASK4**；「HW」现专指每讲一份的课后作业（HW1—HW16）。
> 旧材料中若「HW1—HW4」指大作业，按 TASK1—TASK4 理解。

## 二、逐讲课后作业（HW1—HW16，10%）

HW*n* 对应第 *n* 讲教师指定的学生提交成果，**复用既有课堂产出**，课后按公布截止提交，不另加一份长报告。

- 认定方式：只记**及时性与有效性**，不另评质量分；总评 10 分起计，未按时有效提交每项扣 1 分，同一项只扣一次，扣至 0 分为止。
- 逾期补交保留记录，但不改变原及时性认定。
- 命名 `HWn_学号_姓名`，不套 TASK 的完整复现模板。
- 同一成果在不同评分项复用时，只按各自细则计一次，不重复累加质量分。

## 三、提交渠道

**通过钉钉课程群单聊提交给何老师本人**，不发群文件、不发群聊天。GitHub 本仓库只用于分发资料，不收作业。

提交后不逐条回复；每讲结束后群内发布一次《收件核对表》，学生自行核对，有异议须在发布后 48 小时内提出。

完整的命名规则、包结构、退回情形与截止判定见 **[提交规范（学生版）](提交规范.md)**。
大作业开工前复制 `提交模板/TASKn_学号_姓名/`，改名为 `TASKn_学号_姓名` 再填内容；逐讲 HW 直接用课堂成果文件按 `HWn_学号_姓名` 打包，无需套模板。

## 四、提交要求

- 文件名严格为 `TASKn_学号_姓名.zip` 或 `HWn_学号_姓名.zip`（如 `TASK1_20260001_张三.zip`、`HW3_20260001_张三.zip`），用下划线分隔，不带空格、括号或"最终版"字样。命名不符按退回处理，退回期间不计为已提交。
- 大作业须交付可运行的 Notebook 或脚本 + 数据来源说明 + 运行步骤；关键结论须能由随附输出复算。
- `outputs/` 须为真实运行产物，含 `run.log`。教师会重跑比对关键数字；对不上且无法解释的，该项按未完成处理。
- 引用论文、数据库与 API 时给出 DOI/版本/访问日期；数据许可与单位必须写在报告开头。
- 使用 AI 辅助须声明任务、输入、输出与个人独立复核部分；不得把模型生成内容直接当作实验结论。
- 包内不得含 API 密钥、个人凭据或未授权的科研原始数据。检出密钥的包判结构不合格，须吊销后重发清理版。
- 数据合计超过 20 MB 不入包，在 `data/README.md` 写明来源、许可、获取方式与 SHA256。
- 选做题用于拓展，不因具备 GPU 或付费服务而获得额外总评优势。提交渠道与形式同样不影响评分：钉钉单聊是唯一渠道，不需要 GitHub 账号。
