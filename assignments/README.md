四次作业占总评 30%，每次按 100 分评定、各占总评 7.5%。任务范围、分值与截止以本目录和各讲说明为准，**优先于历史讲义中的旧作业描述**。

## 统一评分维度

每项作业按四维评定：**正确性 40%、结果证据 30%、分析与局限 20%、复现与引用 10%**。四维用于打分，不与上表的任务百分比重复相加——任务百分比决定各小题的分值，四维决定每一小题内部怎么给分。

## 提交渠道

**通过钉钉课程群单聊提交给何老师本人**，不发群文件、不发群聊天。GitHub 本仓库只用于分发资料，不收作业。

提交后不逐条回复；每讲结束后群内发布一次《收件核对表》，学生自行核对，有异议须在发布后 48 小时内提出。

完整的命名规则、包结构、退回情形与截止判定见 **[提交规范（学生版）](提交规范.md)**。开工前先复制 `提交模板/HWx_学号_姓名/`，改名为 `类型_学号_姓名` 再填内容。

## 提交要求

- 文件名严格为 `类型_学号_姓名.zip`（如 `HW1_20260001_张三.zip`），用下划线分隔，不带空格、括号或"最终版"字样。命名不符按退回处理，退回期间不计为已提交。
- 交付可运行的 Notebook 或脚本 + 数据来源说明 + 运行步骤；关键结论须能由随附输出复算。
- `outputs/` 须为真实运行产物，含 `run.log`。教师会重跑比对关键数字；对不上且无法解释的，该项按未完成处理。
- 引用论文、数据库与 API 时给出 DOI/版本/访问日期；数据许可与单位必须写在报告开头。
- 使用 AI 辅助须声明任务、输入、输出与个人独立复核部分；不得把模型生成内容直接当作实验结论。
- 包内不得含 API 密钥、个人凭据或未授权的科研原始数据。检出密钥的包判结构不合格，须吊销后重发清理版。
- 数据合计超过 20 MB 不入包，在 `data/README.md` 写明来源、许可、获取方式与 SHA256。
- 选做题用于拓展，不因具备 GPU 或付费服务而获得额外总评优势。提交渠道与形式同样不影响评分：钉钉单聊是唯一渠道，不需要 GitHub 账号。
